# Этап 4. Dashboard и аналитика

Дата актуализации: 2026-07-16.

Документ фиксирует правила расчёта dashboard-аналитики MVP: стоимости портфеля, структуры, внешних денежных потоков и XIRR.

## Источник данных

Analytics view model собирается на сервере в `app/src/lib/portfolio/data.ts` через `buildPortfolioAnalytics` из `app/src/lib/portfolio/analytics.ts`.

Входные данные:

- `operations` — история импортных и ручных операций;
- `positions` — рассчитанные позиции по инструментам;
- `cashBalances` — рассчитанные денежные остатки;
- `family.baseCurrency` — базовая валюта семьи.

Отменённые операции с `cancelled_at` не участвуют в аналитике.

## Стоимость портфеля

Текущая стоимость портфеля:

```text
totalValue = investedValue + cashValue
```

Где:

- `investedValue` — сумма `market_value` активных позиций в базовой валюте;
- если `market_value` отсутствует, используется `book_value`;
- `cashValue` — сумма денежных остатков в базовой валюте.

Если позиция или денежный остаток выражены не в базовой валюте семьи, значение не пересчитывается фиктивно. Такая строка помечает аналитику как частичную, пока нет отдельной FX-модели.

## P&L

Текущий dashboard показывает нереализованный P&L:

```text
unrealizedPnl = sum(position.unrealized_pnl)
```

Ограничения:

- realized P&L отдельно не считается;
- P&L не является денежно-взвешенной доходностью;
- для не-базовых валют значение не пересчитывается без FX-модели.

## Внешние денежные потоки

Dashboard показывает внешние притоки и выводы капитала.

Входят:

- `deposit` — внешний приток;
- `withdrawal` — внешний вывод.

Не входят:

- `buy`;
- `sell`;
- `fx`;
- `transfer_in`;
- `transfer_out`;
- отменённые операции.

Причина: сделки, FX и переводы между своими счетами меняют структуру портфеля, но не являются внешним вводом или выводом капитала для всего семейного портфеля.

Для периода:

```text
inflows = sum(abs(net_amount) for deposit)
outflows = sum(abs(net_amount) for withdrawal)
net = inflows - outflows
```

Поддерживаемые периоды:

- `1M` — последний календарный месяц от даты актуальности;
- `3M` — последние три календарных месяца;
- `YTD` — с 1 января года даты актуальности;
- `1Y` — последние 12 календарных месяцев;
- `All` — вся доступная история.

Дата актуальности берётся как самая поздняя дата из операций, оценок позиций и снимков cash. Если данных нет, используется текущая дата сервера.

## Помесячная динамика потоков

Для выбранного периода внешние потоки группируются по месяцу:

```text
bucket.key = YYYY-MM
bucket.inflows = sum(deposit)
bucket.outflows = sum(withdrawal)
bucket.net = bucket.inflows - bucket.outflows
```

Эта динамика нужна для визуальной проверки: пользователь должен видеть, в какие месяцы были основные внесения или выводы.

## XIRR

XIRR считается по внешним потокам и конечной оценке портфеля.

Правило знаков:

- `deposit` становится отрицательным cash-flow, потому что инвестор внёс деньги в портфель;
- `withdrawal` становится положительным cash-flow, потому что инвестор забрал деньги из портфеля;
- текущая стоимость портфеля добавляется как положительный terminal cash-flow на дату актуальности.

Формула:

```text
NPV(rate) = sum(amount_i / (1 + rate) ^ yearFraction_i)
XIRR = rate, при котором NPV(rate) = 0
```

Для MVP используется база `365` дней:

```text
yearFraction_i = days_between(first_cash_flow_date, cash_flow_date_i) / 365
```

Алгоритм:

1. Проверить входные данные.
2. Попробовать несколько стартовых ставок для Newton-Raphson.
3. Если Newton-Raphson не сходится, использовать поиск интервала и бисекцию.
4. Если устойчивого решения нет, вернуть диагностический статус вместо числа.

Диагностические статусы:

- `ready` — XIRR посчитан;
- `insufficient_cash_flows` — недостаточно потоков;
- `missing_valuation` — нет положительной текущей оценки;
- `no_sign_change` — нет потоков с разными знаками;
- `not_converged` — численный метод не сошёлся.

## XIRR detail

Dashboard показывает `XirrDetail`, чтобы расчёт был проверяемым:

- итоговый статус;
- значение XIRR;
- дата актуальности;
- terminal value;
- строки cash-flow;
- сумма внешних внесений;
- сумма внешних выводов;
- количество пропущенных потоков не в базовой валюте;
- причина недоступности расчёта.

Строки XIRR:

- `external_inflow` — внесение, отрицательная сумма;
- `external_outflow` — вывод, положительная сумма;
- `terminal_value` — текущая оценка портфеля, положительная сумма.

## Структура портфеля

Dashboard строит три среза:

1. По классам активов:
   - позиции группируются по `asset_type_code`;
   - cash добавляется отдельным классом `cash`.
2. По валютам:
   - учитываются позиции;
   - учитываются денежные остатки.
3. По счетам:
   - учитываются позиции;
   - учитываются денежные остатки.

Каждый срез содержит:

- `key`;
- `label`;
- `value`;
- `percent`;
- `count`;
- `href`;
- `status`.

`status = partial`, если часть значений не может быть пересчитана в базовую валюту.

## Частичные данные

Аналитика не должна молча превращать неизвестные значения в нули.

Пользователь видит предупреждения, если:

- нет рыночной цены и используется балансовая стоимость;
- есть данные не в базовой валюте без FX-пересчёта;
- XIRR недоступен;
- портфель пуст.

## Известные ограничения

- Нет исторической FX-модели для полного пересчёта всех валют.
- XIRR считается только по всему семейному портфелю.
- Нет отдельного XIRR по счёту, активу или портфелю.
- Realized P&L не выделен отдельной метрикой.
- Дивиденды, купоны, комиссии и налоги не выделены в отдельные аналитические классы.
- Нет группировки малых долей в `Прочее`.
- Нет экспорта dashboard-аналитики.
